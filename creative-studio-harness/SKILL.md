# 中文创作工作室 Harness

这个 Skill 把一个内容项目组织成可持续运行的创作工作室。它提供空间初始化、已有空间接入、工作室配置、项目生产、阶段 Review、工具登记、发布复盘和资产沉淀。它不内置任何特定 IP、角色、平台或供应商；黑手套君之类的项目规则只能作为使用者自己的配置写入工作空间。

## 何时使用

适用于：

- 想从零建立一个中文创作 Harness；
- 已有散落的脚本、素材、提示词和数据，想接入统一空间；
- 要推进一个项目的选题、内容骨架、脚本、分镜、执行、发布或复盘；
- 要把经验证的角色、视觉、声音、提示词或数据结论沉淀为可复用资产。

不要因为用户只要一个标题、一段文案或一次普通改稿就启动完整工作室流程；先完成当前小任务，除非用户明确要建立或使用 Harness。

## 首次使用是强制配置步骤

当目标空间不存在，或空间还没有可用的工作室配置时：

1. 先检查当前目录和用户指定路径，不凭空假设已有结构。
2. 使用 `scripts/init_workspace.py` 创建中文工作空间，或读取 `references/已有空间接入.md` 接入现有空间。
3. 引导用户完成 `00_创作中枢/工作室配置.md` 的 v0.1：至少写清工作室名称、一句话定位、核心受众、主要内容形式、基本内容承诺、表达方向、一个明确禁区和当前可用工具。
4. 不确定的内容写成“待确认”，不要替用户发明 IP 事实；在 `初始化记录.md` 记录已确认、暂定和待补项。
5. 配置达到最小可运行状态后，再创建第一个项目。

用户可以让 Skill 根据已有对话、文件和素材生成配置草稿，但写入事实源前要把“原文事实、用户明确决定、推断、待确认”分开呈现。已有配置不完整时只补缺项，不擅自重排或覆盖旧文件。

## 工作空间原则

- 用户可见的工作空间目录和模板使用中文；Skill 包的 `SKILL.md`、`agents/`、`references/`、`scripts/` 等技术目录保留规范命名。
- `00_创作中枢` 存长期规则和当前工作台；`01_设定与生产资产库` 存跨项目复用资产；`02_灵感与选题池` 存未立项方向；`03_内容生产` 存单项目全过程；`04_数据反馈与复盘` 存平台事实和实验；`05_成品归档` 存最终交付；`06_参考资料与输入` 存未结构化来源；`99_模板` 存可复制模板。
- 长期规则、单项目决定、原始输入、观察事实和未经验证的假设分开存放。不要用一次项目的结果自动改写工作室长期规则。
- 项目文件保留版本和返工痕迹；新版本追加或另存，不覆盖已经被主创确认的来源。
- 工具是可替换连接器。先看 `00_创作中枢/工具登记表.md` 和 `references/工具登记规范.md`；没有工具、未授权或调用失败时，不声称已经生成或发布。

## 当前请求的路由

先判断用户目前处于哪种模式，再只读取相关参考：

- **初始化/接入**：读取 `references/初始化向导.md` 或 `references/已有空间接入.md`，必要时运行 `inspect_workspace.py`、`init_workspace.py`。
- **工作室配置**：读取 `references/工作室配置规范.md`，更新 v0.1 或后续版本，并保留变更记录。
- **新项目**：先读工作台、内容形式策略和选题池，再运行 `create_project.py`，使用项目模板。
- **内容开发**：读取 `references/内容开发与门禁.md`，完成内容卡、探索、内容骨架和观看体验预审；未通过门禁不要直接进入分镜或生图。
- **分镜/执行**：读取 `references/分镜执行与质检.md`，区分事件、节拍、镜头和生成任务；根据用户选择设计表达、参考图职责、声音和连续性。
- **发布/复盘**：读取 `references/发布复盘与沉淀.md`，把平台快照、评论和成片事实与创作初心、设计、预期分开对照。
- **空间检查**：运行 `validate_workspace.py`，再根据报告修复缺失项；不要为了“通过检查”填入虚构内容。

## 阶段门禁

通用门禁如下，项目可以在自己的配置里调整名称和适用范围：

```text
工作室 v0.1
  → 内容卡与内容承诺
  → 内容骨架与节拍/观看体验预审
  → 分镜和执行计划 Review
  → 执行素材生成与验收
  → 粗剪、发布包装
  → 平台数据与评论复盘
  → 资产沉淀、实验和规则迭代
```

门禁的作用是发现内容、节奏、可拍性、连续性或证据问题；它不是要求每个项目都使用同一套评分，也不授权额外的付费生成、发布或外部写入。需要真实调用外部工具时，遵守当前会话已有授权和工具登记中的确认要求。
