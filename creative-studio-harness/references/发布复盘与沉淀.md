# 发布复盘与沉淀

## 发布包装

标题、封面、简介、标签和片头共同构成观看承诺。先检查信息是否准确、主体和事件是否可读，再讨论点击张力。没有真实成片证据时不要承诺一个素材里不存在的结果。

## 数据记录

每个渠道单独记录作品身份、发布版本、采集时间、统计窗口和来源。缺失值写缺失，不用 0 代替；累计值、区间值和不同版本不要混算。评论保留采样范围、时间和原文来源。

## 复盘结构

每轮按以下顺序写：

1. 事实：发布了什么，实际数据和评论是什么。
2. 设计对照：初心、设计、预期和最终执行分别是什么。
3. 可能解释：哪些原因与证据相符。
4. 替代解释：哪些变量同时变化，不能直接归因。
5. 下一步实验：下一条只优先改变一个主要变量，并写清指标和比较窗口。

## 资产沉淀

跨项目复用、稳定定义主体、明显提效、被评论/数据验证或是未来生成必须保持的锚点，才进入资产库。一次性桥段、单条文案和未验证判断留在项目里。资产登记来源、状态、复用条件和路径；旧版本不覆盖。
